# Mimir

Monorepo: [apps/server](apps/server) (NestJS backend, `@mimir/server`) + [apps/web](apps/web) (Next.js app, `@mimir/web`).

## Commands

- `pnpm dev` — server + web in parallel (server on :9090, web on :3000; :9000 is MinIO)
- `pnpm --filter @mimir/server prisma:migrate` — apply migrations (wraps `prisma migrate dev`, loads root `.env`)
- `pnpm --filter @mimir/server generate` — regenerate Prisma client (needed after fresh install; loads root `.env`)
- `pnpm --filter @mimir/server openapi` — regenerate OpenAPI spec + types
- `pnpm --filter @mimir/web generate:api-types` — sync spec into web (calls the server script)
- `pnpm --filter @mimir/web test` — vitest
- `pnpm --filter @mimir/web test:e2e` — Playwright. **Kill any :3000 dev server first** (or use `pnpm test:e2e:ui`).

## Code conventions (must follow)

Apply these to all new and edited code. If existing code violates a rule, fix only what you are touching — do not proactively refactor unrelated files.

### File naming

- **All filenames use camelCase.** `userProfile.tsx`, `apiClient.ts`, `useFlashcardSearch.ts`.
- Do NOT use PascalCase (`UserProfile.tsx`) or kebab-case (`user-profile.tsx`), even for React components.
- Exception: shadcn/ui primitives under `apps/web/components/ui/` stay kebab-case (they are generated by the shadcn CLI — do not rename them).
- Server (NestJS) files keep the NestJS dotted convention: `auth.controller.ts`, `login-attempts.service.ts`, `create-user.dto.ts`. Do NOT rename these to camelCase.

### Identifier naming

- **camelCase for everything in TypeScript**, including module-level constants. Write `const pageSize = 20`, not `const PAGE_SIZE = 20`. Write `const features = [...]`, not `const FEATURES = [...]`.
- PascalCase only for: React components, TS types/interfaces, classes, enums.
- SCREAMING_SNAKE_CASE is reserved for: env var names as they appear in `process.env.FOO`, and nothing else.
- Booleans read as predicates: `isLoading`, `hasError`, `canEdit`.

### UI

- **Use shadcn/ui primitives** from `apps/web/components/ui/` (Button, Input, Dialog, Card, Select, Tabs, Form, etc.). Do not hand-roll raw `<button>`, `<input>`, or `<dialog>` elements when a shadcn primitive exists.
- If a needed shadcn primitive is missing, add it with `pnpm dlx shadcn@latest add <name>` — do not copy source from other projects and do not build your own.
- Do NOT introduce other UI libraries (MUI, Chakra, Ant, Mantine, etc.).
- **Icons: lucide-react only.** No heroicons, no react-icons, no inline SVG paths.
- **Styling: Tailwind utility classes.** Do not add CSS modules, styled-components, or emotion.

### Imports

- Use the `@/` alias for cross-directory imports in `apps/web`. Do not use `../../` chains that leave the current feature folder.
- Sibling imports within the same folder may use `./`.

### React / Next.js

- Named exports for React components (`export function ModuleCard() {}`), not default exports.
- Server components by default in the Next.js app router; add `'use client'` only when a component needs interactivity, state, or browser APIs.
- Data fetching: TanStack Query hooks under `apps/web/lib/hooks/`. Do not introduce a competing data-fetching library.
- Forms: react-hook-form + zod resolvers via `@hookform/resolvers`. Do not use Formik or hand-rolled state.

### Backend (NestJS)

- Every feature is a module under `apps/server/src/modules/<feature>/` with `<feature>.module.ts`, `<feature>.controller.ts`, `<feature>.service.ts`, and a `dtos/` folder for DTOs.
- DTOs use `class-validator` decorators. Global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })` is on — never send fields the DTO does not declare, or the request 400s.
- **Response shape** `{ ok, message, data }` is applied by the global interceptor. Return the raw payload from the controller; do not wrap it yourself. The axios client on the web unwraps it — hooks see just `data`.
- When a DTO field is nullable or a union, add explicit `@ApiProperty({ type: String, nullable: true })` — without it, `openapi-typescript` emits `Record<string, never>` on the web side.

### After changes

- Run `pnpm --filter @mimir/web lint` (and `@mimir/server` equivalent) before reporting a task complete. Fix any lint errors you introduce.
- If a change touches server DTOs or endpoints, regenerate types: `pnpm --filter @mimir/server openapi && pnpm --filter @mimir/web generate:api-types`.

## Other conventions

- **Web auth**: access token lives in memory only; refresh token via HttpOnly cookie. [apps/web/src/lib/api/token-store.test.ts](apps/web/src/lib/api/token-store.test.ts) is the regression guard.
- **Web OAuth**: browser must hit the real backend origin (VITE_BACKEND_ORIGIN, defaults to `http://localhost:9090`) so it can follow the redirect chain to Google and back.
- **Playwright**: mock APIs with `page.route(/regex/, ...)` — no MSW browser worker. Match by path only (works whether VITE_API_BASE_URL is the proxy `/api` or the direct backend URL).

## Gotchas

- **Native macOS Postgres** intercepts `localhost:5432` — the mimir docker container gets shadowed. See [memory/env_postgres_conflict.md](.). Use a different port or stop native PG before `prisma db push`.
- **JWT type imports**: `@types/jsonwebtoken@9.0.10+` requires `StringValue` from `ms` for `signOptions.expiresIn`. Only `@types/ms@2.1.0+` provides it (through the `ms` namespace).
- **Backend register endpoint** does not accept `displayName` — only `email`, `username`, `password`. The user's display name is derived from `username` and can be updated via `PATCH /users/me` later.
- **useMutation + useEffect**: don't put the mutation *object* in the deps array — it changes on every state transition. Destructure `mutate` (stable) and depend on that, or you'll race with React's dev-mode double-invoke.

## Layout

- [apps/server](apps/server) — NestJS. Modules under `src/modules/{auth,users,study-sets,srs,...}`.
- [apps/web](apps/web) — Vite + React 18. Routes in `src/routes/`, feature UI in `src/features/`, shared UI kit in `src/components/ui/` (shadcn/Radix), API layer in `src/lib/api/`, i18n in `src/lib/i18n/`.
- [docs/](docs/) — project-wide TDD, roadmap, requirements. `Mimir_TDD_v1.md` in `docs/` is the canonical architecture doc (the copy under `apps/web/` will drift).
- [monitoring/](monitoring/) — Prometheus + Grafana stack (opt-in via `docker-compose.monitoring.yml`).
